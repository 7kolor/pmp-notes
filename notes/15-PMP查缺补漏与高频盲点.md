## 1. 计算题：不只是背公式，更是懂“含义”

您在成本管理错题中表现出对 **预测性指标** 理解的偏差。请记住，计算题不仅考算术，更考**指标背后的管理意义**。

### 1.1 基准 (Baseline) vs. 预测 (Forecast)
*   **BAC (完工预算)**: **基准**。是“原计划”的总预算。除非有批准的变更，否则**不动**。
*   **EAC (完工估算)**: **预测**。是基于当前绩效（CPI）推算的“新总预算”。**是动态变化的**。
    *   *场景*: 项目做了一半，CPI=0.8（超支），老板问“按这个样子下去，最后要花多少钱？” -> 算 **EAC**。
*   **ETC (完工尚需估算)**: **预测**。是“还需要”多少钱。
    *   *公式*: `ETC = EAC - AC`。
*   **TCPI (完工尚需绩效指数)**: **预测/目标**。是“为了不超预算，剩下的活儿得干多快/多省”。
    *   *含义*: 如果TCPI > 1，说明剩下的工作很难（因为资金紧缺）；如果TCPI < 1，说明剩下的工作很轻松。

### 1.2 CPI/SPI 的本质
*   **CPI (成本绩效指数)**: **资金使用效率**。
    *   *误区*: 只是一个数字。
    *   *正解*: **“每花1块钱，办了价值多少钱的事”**。CPI=0.8 意味着每花1块钱，只办了0.8元的事（亏了）。
*   **SPI (进度绩效指数)**: **时间利用效率**。
    *   *正解*: **“计划做1块钱的活，实际做了多少”**。

## 2. 工具与技术：高频“混淆矩阵”

您的错题中多次出现工具选择错误（如核查表 vs 直方图，WBS vs 活动列表）。以下是**必考**的区分点：

### 2.1 数据收集 vs. 数据表现
| 场景 | **数据收集 (Data Gathering)** | **数据表现 (Data Representation)** |
| :--- | :--- | :--- |
| **找缺陷数据** | **核查表 (Checksheets)**<br>*动作: 计数、记录* | **帕累托图 (Pareto)**<br>*动作: 排序、找重点(80/20)* |
| **看过程状态** | **抽样 (Sampling)**<br>*动作: 选一部分查* | **控制图 (Control Chart)**<br>*动作: 看趋势、看稳定性(七点规则)* |
| **找原因** | **头脑风暴**<br>*动作: 发散思维* | **因果图 (鱼骨图)**<br>*动作: 结构化展示根因* |
| **看变量关系** | - | **散点图 (Scatter Diagram)**<br>*动作: 看XY相关性* |

### 2.2 范围 vs. 进度工具
| 维度 | **范围管理 (Scope)** | **进度管理 (Schedule)** |
| :--- | :--- | :--- |
| **核心产出** | **WBS (工作分解结构)** | **活动清单 (Activity List)** |
| **关注点** | **“做什么” (What)**<br>名词、可交付成果 | **“怎么做/何时做” (How/When)**<br>动词、动作 |
| **层级** | 工作包 (最底层) | 活动 (比工作包更细，用于估算时间) |
| **错题矫正** | 制定WBS时，不要列入具体“行动”（如“测试软件”是活动，“测试报告”是WBS成果）。 | 估算时间是针对“活动”的，不是针对“需求”或“工作包”直接估算的。 |

### 2.3 资源管理双子星
| 工具 | **资源日历 (Resource Calendar)** | **RACI 矩阵** |
| :--- | :--- | :--- |
| **核心功能** | **可用性 (Availability)** | **职责 (Responsibility)** |
| **解决问题** | “这个人在这个时间段**有空吗**？”<br>（请假、倒班、跨时区） | “这件事**归谁管**？”<br>（推诿、职责不清、没人拍板） |
| **错题矫正** | 安排会议/活动 -> 查**日历**。 | 团队冲突/没人负责 -> 查**RACI**。 |

## 3. PMI 道德与专业行为规范 (Code of Ethics)

虽然没有直接出现在您的错题集里，但这部分是PMP考试的**底层逻辑**（必考4-5题，且融入情景题）。

### 四大核心价值观
1.  **责任 (Responsibility)**:
    *   **所有权**: 对决策和行动负责（包括错误）。
    *   **考点**: 犯了错（如估算错误、进度延误），**首先承认并告知相关方**，而不是掩盖或推卸。
2.  **尊重 (Respect)**:
    *   **考点**: 尊重不同文化、观点。在发生冲突时，**直接沟通**，不背后议论。谈判时追求双赢。
3.  **公正 (Fairness)**:
    *   **考点**: 决策透明，**利益冲突 (Conflict of Interest)** 必须**主动申报**（如：供应商是你亲戚）。申报后通常回避或由第三方决策。
4.  **诚实 (Honesty)**:
    *   **考点**: 提供真实信息。**不撒谎**，哪怕是善意的谎言。如实报告项目状态（哪怕是红灯）。

## 4. 敏捷/混合环境的“隐形”考点

### 4.1 敏捷章程 (Agile Charter)
*   **定义**: 敏捷项目也有章程！但它更轻量。
*   **核心内容**: **愿景 (Vision)**、**使命 (Mission)**、**成功标准 (Success Criteria)**。
*   **用途**: 它是团队的“北极星”。当测试人员进行**探索性测试**，或者团队迷茫时，看章程。

### 4.2 消除孤岛 (Silos)
*   **现象**: 前端等后端，测试等开发。这是传统“职能型”团队的弊端。
*   **敏捷解法**:
    1.  **首选**: **跨职能团队** (Cross-functional)。大家坐在一起，还是一个人能干多种活（T型人才）。
    2.  **次选**: **密切协作**。如果必须分工，解决依赖靠的是“人与人的直接沟通”，而不是靠PM传话。

### 4.3 敏捷中的“合同”
*   **传统**: 固定总价（风险在卖方，变更难）。
*   **敏捷**: 推荐 **“工料合同 (T&M)”**（灵活，风险共担）或 **“得失与共 (Shared Risk/Reward)”**。
*   **考点**: 如果需求不明确且需要快速开始，选 **工料合同**。
