# 考前冲刺核心速记

本文档专为考前突击整理，汇集了 PMP 考试中最核心、最高频的考点、底层逻辑及做题技巧。内容高度概括，旨在帮助考生在短时间内建立“PMP 思维”，快速排除错误选项。

## 1. 考试底层逻辑与心态 (Mindset)

PMP 考试不仅考知识，更考**思维方式**。遇到模棱两可的题目，请默念以下原则：

*   **PMP 核心价值观**：
    *   **理智**：不情绪化，不随意开除人，不随意上报，不随意拒绝。
    *   **分析**：**先分析，后行动**。凡事要有依据（数据、计划、文件）。
    *   **合规**：严格遵守法律法规和公司政策（EEF），绝不踩红线。
    *   **双赢**：追求相关方满意，追求团队成长，追求组织利益最大化。
    *   **敏捷**：拥抱变更，以价值为导向，去繁从简。

*   **做题“十字真言”**：
    *   **分析**（Analyze）：看到问题先评估影响。
    *   **沟通**（Communicate）：相关方问题多半是没沟通好。
    *   **记录**（Document）：凡事要留痕（日志、登记册）。
    *   **流程**（Process）：变更要走流程，收尾要归档。
    *   **仆人**（Servant）：帮团队扫除障碍，而不是发号施令。

## 2. 核心考点速查 (Process & People)

### 2.1 变更控制流程 (ICC) - 预测型项目必考
只要涉及基准（范围、进度、成本）修改，必须严格按此顺序：
1.  **记录**：收到变更请求，先记录。
2.  **分析**：评估对项目铁三角（范围/进度/成本/质量/风险）的影响。
3.  **审批**：提交给 CCB（变更控制委员会）或发起人审批。
4.  **更新**：批准后，更新项目管理计划和基准。
5.  **通知**：通知受影响的相关方。
6.  **执行**：实施变更。
*   **口诀**：**“变更是为了以此为据，不是为了拒绝。没分析前别瞎动。”**

### 2.2 冲突解决五大法宝
团队吵架怎么管？按优先级排序：
1.  **合作/解决问题 (Collaborate/Problem Solve)**：**（首选）** 双方公开讨论，寻找根源，达成双赢。
2.  **妥协/调解 (Compromise/Reconcile)**：各退一步，求同存异，双输（或半赢）。
3.  **缓和/包容 (Smooth/Accommodate)**：强调共性，淡化分歧，求一时太平，问题没解决。
4.  **撤退/回避 (Withdraw/Avoid)**：暂缓处理，等冷静下来再说（适用于情绪激动或此时非核心问题）。
5.  **强迫/命令 (Force/Direct)**：**（最差）** 利用权力强行解决，赢-输模式（紧急情况或合规问题除外）。

### 2.3 塔克曼团队发展阶段
判断团队处于哪个阶段，采取对应策略：
1.  **形成期 (Forming)**：彬彬有礼，茫然。 -> **命令/指导式**。
2.  **震荡期 (Storming)**：**冲突高发**，互不服气。 -> **教练/影响式**（PM 介入解决冲突）。
3.  **规范期 (Norming)**：开始磨合，建立习惯。 -> **参与/支持式**。
4.  **成熟期 (Performing)**：高效协作，自我管理。 -> **授权/委派式**。
5.  **解散期 (Adjourning)**：庆功，释放资源。

### 2.4 风险管理逻辑
*   **未知风险 (Unknown Unknowns)** -> 动用**管理储备** (需走变更)。
*   **已知风险 (Known Unknowns)** -> 动用**应急储备** (PM 可直接用)。
*   **风险发生时**：
    1.  查阅**风险登记册**（看有没有应对计划）。
    2.  如果有计划 -> **执行计划**。
    3.  如果没计划（新风险） -> **更新风险登记册** -> **定性/定量分析** -> **制定应对措施**。

## 3. 敏捷/混合型项目必考点 (Agile)

**占比约 50%，核心是“适应性”和“价值”。**

### 3.1 敏捷四大价值观
*   **个体和互动** 高于 流程和工具。
*   **可工作的软件** 高于 详尽的文档。
*   **客户合作** 高于 合同谈判。
*   **响应变化** 高于 遵循计划。

### 3.2 关键角色与职责 (Scrum)
*   **Product Owner (PO)**：**管“做什么”**。负责产品价值、排序 Backlog、定义优先级。**（只有 PO 能决定需求做不做、先做哪个）**
*   **Scrum Master (SM)**：**管“流程/人”**。仆人式领导，清除障碍，屏蔽干扰，确保流程正确。**（不替团队做技术决定）**
*   **Team (开发团队)**：**管“怎么做”**。自组织，跨职能，自己估算，自己认领任务。

### 3.3 关键概念辨析
*   **MVP (最小可行性产品)**：为了**学习**和**验证**假设，用最小代价做的版本。
*   **MMF (最小适销特性)**：为了**赚钱**和**交付价值**，最小的一组功能集。
*   **DoD (完成的定义)**：**质量标准**。整个团队的承诺，不仅是代码写完，还包括测试、文档等。不达 DoD 不能进 Review 会议。
*   **AC (验收标准)**：**用户需求**。针对具体 User Story 的验收条件。

### 3.4 敏捷问题解决套路
*   **团队进度慢？** -> 查 WIP（在制品限制），是不是多任务切换太多。
*   **相关方想插队加需求？** -> 让 PO 放入 Backlog 排序，下个迭代做（不要干扰当前 Sprint）。
*   **团队有技术分歧？** -> 团队自己决定（SM 引导，但不拍板）。
*   **发现严重 Bug？** -> 立即解决（敏捷提倡内建质量，不留技术债务）。

## 4. 必背公式与关键指标

考前不用背复杂计算，记住**判断逻辑**最重要：

### 4.1 挣值管理 (EVM)
*   **CV (成本偏差) = EV - AC**
*   **SV (进度偏差) = EV - PV**
*   **CPI (成本绩效) = EV / AC**
*   **SPI (进度绩效) = EV / PV**
*   **口诀**：**大于 1 都是好消息！**
    *   CPI > 1：省钱； CPI < 1：超支。
    *   SPI > 1：提前； SPI < 1：落后。

### 4.2 三点估算 (PERT)
*   **贝塔分布 (常用)**：(最悲观 + 4 * 最可能 + 最乐观) / 6
*   **用途**：题目给出三个时间值，问你估算工期，直接套公式。

## 5. 易混淆概念“一刀切”

*   **EEF vs OPA**：
    *   **EEF (事业环境因素)**：**身不由己**。法律、汇率、软件系统、人事制度。 -> **只能适应**。
    *   **OPA (组织过程资产)**：**前人财富**。模板、经验教训、历史档案。 -> **可以裁剪、必须更新**。

*   **质量保证 (QA) vs 质量控制 (QC)**：
    *   **QA (管理质量)**：**管过程**。防止出错，审计流程，持续改进。 -> **事前/事中**。
    *   **QC (控制质量)**：**管结果**。检查产品，找 Bug，测试。 -> **事后**。

*   **风险应对策略**：
    *   **规避 (Avoid)**：**根除**。修改计划、取消项目、通过测试消除隐患。
    *   **减轻 (Mitigate)**：**降低**。降低概率或影响（如：多备一个发电机、多测几遍）。
    *   **转移 (Transfer)**：**甩锅**。买保险、外包、签保修合同。
    *   **接受 (Accept)**：**躺平**。建立应急储备（主动），或什么都不做（被动）。

*   **资源平衡 vs 资源平滑**：
    *   **平衡 (Leveling)**：**动关键路径**。资源不够，延长期限。 -> **工期会变**。
    *   **平滑 (Smoothing)**：**不动关键路径**。利用浮动时间削峰填谷。 -> **工期不变**。

## 6. 答题红绿灯 (Keywords)

### 🟢 绿灯词 (优先选)
*   **分析/评估 (Analyze/Assess)**：永远的第一步。
*   **审查 (Review)**：查阅计划、日志。
*   **引导/促进 (Facilitate)**：SM 的核心动作。
*   **面对面 (Face-to-face)**：最高效沟通。
*   **协作 (Collaborate)**：解决冲突首选。
*   **经验教训 (Lessons Learned)**：总结、分享、避免重蹈覆辙。
*   **根本原因分析 (Root Cause Analysis)**：治本。

### 🔴 红灯词 (直接排除)
*   **立即拒绝/立即实施**：不做分析的行动都是错的。
*   **上报 (Escalate)**：除非天塌下来（超出权限），否则 PM 自己扛。
*   **惩罚/开除 (Punish/Fire)**：PMP 不搞这一套。
*   **推卸责任**：把问题推给别人。
*   **忽略/暂缓**：问题必须解决，不能拖。
