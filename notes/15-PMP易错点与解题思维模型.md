# 15. PMP备考易错点与高分思维模型

> **写在前面**：根据您的近期错题分析，您的知识盲区已经很少，主要的丢分点在于**“解题逻辑”**和**“第一反应”**。本主要用于矫正做题时的“下意识反应”，帮助您建立标准的PMP思维模型。

---

## 1. 您的四大易错模式诊断

### 模式一：急于动手的“行动派” (The Jumper)
*   **症状**：看到问题（如质量缺陷、相关方投诉），直接选择“去解决”（如审计、谈判、赶工）。
*   **PMP思维矫正**：**谋定而后动**。在PMP中，任何行动之前，必须先有**依据**。
*   **口诀**：**先查计划/文档，再分析影响，最后才是行动。**
    *   *错题案例*: 客户投诉产品不达标 -> 您选“谈判/审计” -> 正解是“先**审查质量管理计划**或**验收标准**”。

### 模式二：敏捷/预测“左右互搏” (The Mixer)
*   **症状**：用瀑布的方法解决敏捷的问题，或反之。
*   **PMP思维矫正**：
    *   **预测型 (Waterfall)**：强调**流程合规**（基准、变更控制、CCB）。
    *   **敏捷型 (Agile)**：强调**人与互动**（协作、自组织、适应）。
    *   *错题案例*: 敏捷团队进度慢 -> 您选“加人/加班”（瀑布思维） -> 正解是“维持可持续速度，**减少范围**”（敏捷思维）。

### 模式三：被动应对的“传声筒” (The Messenger)
*   **症状**：遇到困难，倾向于“上报发起人”或“找人帮忙”，或者被动接受现状。
*   **PMP思维矫正**：**PM是第一责任人**。除非超出权限（如项目取消、资金耗尽），否则必须由PM先分析并提出方案。
*   **口诀**：**不要只带问题去汇报，要带方案去汇报。**

### 模式四：概念边界模糊 (The Blur)
*   **症状**：混淆相似的工具或文件。
*   **PMP思维矫正**：精准锁定关键词。
    *   *错题案例*: 安排团队活动看谁有空 -> 您选“人员分配” -> 正解是“**资源日历**”（关键词：可用性/时间段）。

## 2. 万能解题思维模型：M-A-R-A 原则

当题目问 **“项目经理下一步应该做什么？”** 时，请严格按以下顺序进行筛选：

1.  **M (Monitor/Review) - 查阅/审查**
    *   第一反应：我是否有依据？
    *   动作：查阅项目章程、管理计划、验收标准、经验教训、风险登记册。
    *   *场景*：客户说做错了 -> **查验收标准**。

2.  **A (Analyze/Evaluate) - 分析/评估**
    *   第二反应：影响有多大？原因是什么？
    *   动作：影响分析、根本原因分析(RCA)、成本效益分析。
    *   *场景*：发现新风险 -> **定性/定量分析**。

3.  **R (Report/Communicate) - 沟通/汇报**
    *   第三反应：谁需要知道？
    *   动作：通知相关方、提交变更请求（这也是一种沟通）。
    *   *场景*：分析完变更影响 -> **提交CCB** 或 **与相关方沟通方案**。

4.  **A (Act/Execute) - 执行/行动**
    *   第四反应：动手解决。
    *   动作：执行变更、赶工、培训、团队建设。
    *   *场景*：变更获批 -> **实施变更**。

**注意**：如果选项中没有前一步，才选后一步。

## 3. 经典场景“秒杀”技巧

### 场景 A：变更与范围蔓延
*   **题目特征**：客户要求加功能、相关方对范围有异议、团队私自改动。
*   **瀑布解法**：拒绝私下修改 -> **提交变更请求** -> 分析影响 -> CCB审批。
*   **敏捷解法**：不拒绝 -> 找PO -> 放入 **Product Backlog** -> 下次迭代规划。
*   **绝对错误**：直接同意、直接拒绝、让团队加班做、没走流程直接改文档。

### 场景 B：进度落后/资源不足
*   **题目特征**：项目延期、关键路径出问题、有人离职。
*   **解法顺序**：
    1.  **分析影响**：是否影响关键路径？
    2.  **利用浮动时间**：调整非关键路径（资源平滑）。
    3.  **压缩进度**：
        *   有钱/没风险 -> **赶工 (Crashing)**（加人/加班）。
        *   没钱/敢冒险 -> **快速跟进 (Fast Tracking)**（并行）。
    4.  **敏捷特例**：敏捷中**严禁**随意加人（布鲁克斯法则）或强行加班。正确做法是**削减低优先级范围**。

### 场景 C：相关方不满/冲突
*   **题目特征**：相关方抱怨没收到报告、相关方意见不一致、团队吵架。
*   **解法核心**：
    *   **抱怨没收到信息** -> 查 **沟通管理计划**（看规定） -> 查 **相关方登记册**（看需求）。
    *   **意见不一致** -> **引导式研讨会**（跨部门）、**面对面沟通**。
    *   **团队冲突** -> **自组织解决**（敏捷首选） -> **合作/解决问题**（私下、双赢）。

### 场景 D：质量问题
*   **题目特征**：客户拒收、发现大量Bug、流程不规范。
*   **解法辨析**：
    *   **流程/过程**有问题（没按规矩做） -> **管理质量 (QA)** -> 工具：**审计**。
    *   **产品/结果**有问题（东西坏了） -> **控制质量 (QC)** -> 工具：**检查/测试**。
    *   **预防投诉** -> **验收标准 (Acceptance Criteria)**。

## 4. 高频易混概念“一刀切”

| 概念 A | 概念 B | 一刀切区别 |
| :--- | :--- | :--- |
| **资源日历** | **RACI 矩阵** | **日历**看“谁**何时**有空”；**RACI**看“谁**负责**什么”。 |
| **项目章程** | **项目管理计划** | **章程**是“出生证/高层级/授权”；**计划**是“操作手册/详细/怎么做”。 |
| **工作绩效数据** | **工作绩效信息** | **数据**是“原始数”（如：花了5万）；**信息**是“分析结果”（如：SPI=0.8，落后了）。 |
| **管理质量 (QA)** | **控制质量 (QC)** | **QA**管“过程/防患未然”；**QC**管“结果/亡羊补牢”。 |
| **问题日志** | **风险登记册** | **问题**是“已发生/正在发生”；**风险**是“将来可能发生”。 |
| **PO (产品负责人)** | **Team (团队)** | **PO**定“做什么/优先级”；**Team**定“怎么做/工作量”。 |
| **敏捷章程** | **产品路线图** | **章程**是“愿景/使命”；**路线图**是“时间轴/发布计划”。 |

## 5. 考前最后叮嘱

1.  **看到“立即”、“马上”要警惕**：PMP推崇理智，除非是紧急避险（如安全事故），否则“立即行动”通常是错的，前面往往缺了“分析”。
2.  **看到“私下”、“非正式”要分场景**：
    *   **解决冲突**：私下沟通是好的。
    *   **变更/验收**：私下处理是绝对禁止的。
3.  **做题心态**：
    *   你是一个**整合者**，不是技术专家。
    *   你是一个**保姆（仆人）**，不是监工。
    *   你是一个**讲规矩**的人，不是随意变通的人。
